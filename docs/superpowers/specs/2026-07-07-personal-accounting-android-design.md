# 个人本地记账 Android App 首版设计

## 背景和目标

这款 App 是面向个人使用的本地记账工具。首版不追求完整财务管理系统，而是围绕个人日常记账中的几个高频痛点建立清晰结构：

- 每笔支出必须知道从哪个账户或信用卡发生。
- 固定会员、订阅、自动续费可以按周期自动补记。
- 基金定投、黄金定投、理财转入等投资投入可以记录，但不混入普通消费。
- 投资产品的每日或不定期浮盈浮亏来自市值更新，不混入普通收入。
- 用户能同时看清本月真实消费、固定支出、投资投入、投资浮盈浮亏和净资产变化。

首版技术方向为原生 Android：Kotlin + Jetpack Compose + Room。本地数据库为核心存储，不引入账号、服务端或云同步。

## 首版范围

包含：

- 资产账户：现金、银行卡、支付宝、微信等。
- 信用卡账户：支持信用卡消费、还款、未还负债、账单日和还款日字段。
- 普通流水：支出、收入、退款、转账、信用卡还款。
- 周期规则：会员订阅、自动续费、每日/每周/每月定投等。
- 投资资产：基金、黄金、理财等。
- 投资买入/定投：从资产账户扣款并增加投资本金，不计入消费。
- 市值快照：用户手动更新投资当前市值，系统计算浮盈浮亏。
- 首页统计：本月真实消费和当前净资产。
- 手动导出/导入 JSON 文件。

不包含：

- 云同步、账号系统、联网行情接口。
- 贷款、房贷、车贷等长期负债。
- 复式记账、完整资产负债表、完整财务报表。
- 自动后台定时生成账单。首版只在打开 App 时补记到今天。

## 产品架构

首版采用“账户中心 + 流水中心 + 投资中心”的结构。

账户中心负责资产账户和信用卡账户。它回答“钱在哪里”和“从哪里扣除”。普通消费、收入、转账、还款都会明确影响账户余额或信用卡未还负债。

流水中心负责可枚举的资金事件。普通支出、收入、退款、转账和信用卡还款都作为流水记录。周期规则不会直接参与统计，而是生成带来源标记的流水。

投资中心负责投资本金、持仓市值和浮盈浮亏。投资买入和定投会从现金类账户转入投资资产，属于投资投入，不属于消费。市值快照用于计算浮盈浮亏，只影响投资统计和净资产，不进入普通收入。

## 页面结构

底部导航包含五个入口：

- 首页
- 流水
- 账户
- 投资
- 设置

首页展示两个核心指标：

- 本月真实消费：消费支出减退款，不包含账户转账、信用卡还款、投资买入或定投。
- 当前净资产：现金类账户余额 + 投资资产当前市值 - 信用卡未还负债。

首页提供常用快捷操作：

- 记一笔支出
- 记一笔收入
- 投资买入/定投
- 更新投资市值

流水页展示按月流水列表，支持按类型和分类筛选。自动补记生成的流水带明显标记，并支持撤销本次批量补记或跳过某一期。

账户页展示资产账户、信用卡账户和账户明细。信用卡展示未还金额、账单日和还款日。

投资页展示投资资产列表，包括累计投入本金、当前市值、浮盈浮亏和最近一次市值更新时间。

设置页包含分类管理、周期规则管理、导入导出和本地数据维护。

## 数据模型

### Account

账户表。用于资产账户和信用卡账户。

核心字段：

- `id`
- `name`
- `type`: `cash`, `bank_card`, `alipay`, `wechat`, `credit_card`
- `balance`
- `creditLimit`
- `billingDay`
- `repaymentDay`
- `isArchived`
- `createdAt`
- `updatedAt`

普通资产账户使用 `balance` 表示当前余额。信用卡使用 `balance` 表示当前未还负债，消费会增加该值，还款会减少该值。

### Category

分类表。用于普通收支、固定支出和投资投入等。

核心字段：

- `id`
- `name`
- `type`: `expense`, `income`, `transfer`, `investment`
- `isFixedExpense`
- `sortOrder`
- `isArchived`

### Transaction

流水表。记录会影响账户或统计口径的资金事件。

核心字段：

- `id`
- `type`: `expense`, `income`, `refund`, `transfer`, `credit_card_repayment`, `investment_buy`
- `amount`
- `accountId`
- `targetAccountId`
- `categoryId`
- `investmentAssetId`
- `date`
- `note`
- `autoGenerated`
- `recurringRuleId`
- `occurrenceDate`
- `createdAt`
- `updatedAt`

约束：

- 支出必须绑定 `accountId`。
- 转账和信用卡还款必须同时有 `accountId` 和 `targetAccountId`。
- 投资买入必须绑定扣款账户和 `investmentAssetId`。
- 自动周期流水必须写入 `recurringRuleId` 和 `occurrenceDate`。

### RecurringRule

周期规则表。用于生成固定支出、自动续费和定投。

核心字段：

- `id`
- `name`
- `transactionType`
- `amount`
- `accountId`
- `targetAccountId`
- `categoryId`
- `investmentAssetId`
- `frequency`: `daily`, `weekly`, `monthly`
- `startDate`
- `endDate`
- `nextOccurrenceDate`
- `enabled`
- `createdAt`
- `updatedAt`

规则本身不直接参与消费或投资统计。统计只读取它生成的 `Transaction`。

### InvestmentAsset

投资资产表。

核心字段：

- `id`
- `name`
- `type`: `fund`, `gold`, `wealth_management`
- `principal`
- `currentValue`
- `lastValuationDate`
- `isArchived`
- `createdAt`
- `updatedAt`

`principal` 由投资买入和赎回类流水维护。首版可以先支持买入和定投，不要求完整赎回流程。

### ValuationSnapshot

投资市值快照表。

核心字段：

- `id`
- `investmentAssetId`
- `date`
- `value`
- `note`
- `createdAt`

用户手动输入某个投资资产在某天的市值。系统根据当前市值和本金计算浮盈浮亏。

### SkippedOccurrence

跳过周期记录表。用于标记某条周期规则的某一期不生成流水。

核心字段：

- `id`
- `recurringRuleId`
- `occurrenceDate`
- `reason`
- `createdAt`

## 核心业务规则

### 普通支出

用户录入金额、账户或信用卡、分类、日期和备注。资产账户支出减少账户余额。信用卡支出增加信用卡未还负债。

### 信用卡还款

信用卡还款是从资产账户到信用卡账户的资金流。它会减少资产账户余额，并减少信用卡未还负债。信用卡还款不计入消费。

### 账户转账

账户转账只影响两个账户余额，不计入收入或消费。

### 投资买入和定投

投资买入从资产账户扣款，增加投资资产本金。它属于投资投入，不计入本月真实消费。

每日、每周或每月定投通过周期规则生成 `investment_buy` 类型流水。打开 App 时自动补记缺失期数。

### 市值更新和浮盈浮亏

用户在投资页手动输入投资资产当前市值。系统创建 `ValuationSnapshot`，更新 `InvestmentAsset.currentValue` 和 `lastValuationDate`。

浮盈浮亏计算：

```text
浮盈浮亏 = 当前市值 - 投资本金
```

浮盈浮亏不生成普通收入流水，只进入投资统计和净资产计算。

### 本月真实消费

统计范围：

- 包含：普通消费支出。
- 扣减：退款。
- 不包含：账户转账、信用卡还款、投资买入、定投、市值浮盈浮亏。

固定支出可以作为本月真实消费的子集单独展示。固定支出来源包括带 `isFixedExpense` 分类的流水，和由固定支出周期规则生成的流水。

### 当前净资产

计算方式：

```text
当前净资产 = 现金类资产账户余额 + 投资资产当前市值 - 信用卡未还负债
```

## 自动补记设计

App 启动时执行周期补记：

1. 读取启用状态的 `RecurringRule`。
2. 从 `nextOccurrenceDate` 开始，生成不晚于今天的候选日期。
3. 对每个候选日期检查 `SkippedOccurrence`。
4. 按 `recurringRuleId + occurrenceDate` 检查是否已有自动生成流水。
5. 只为缺失日期生成流水。
6. 更新规则的 `nextOccurrenceDate`。
7. 首页展示本次自动补记数量。

防重复规则：

```text
同一 recurringRuleId + occurrenceDate 只能生成一条自动周期流水
```

自动生成的流水必须带：

- `autoGenerated = true`
- `recurringRuleId`
- `occurrenceDate`

撤销本次批量补记时，只删除本次启动生成的自动流水，并回滚受影响的账户和投资资产金额。跳过某一期时，写入 `SkippedOccurrence`，后续启动不再补记这一期。

## 导入导出

首版支持手动 JSON 导出和导入。

导出文件包含：

- schema version
- accounts
- categories
- transactions
- recurring rules
- investment assets
- valuation snapshots
- skipped occurrences

导入时先校验 schema version 和基础字段。校验失败时不覆盖现有数据。首版导入策略采用整体校验后写入，避免半导入状态。

## 错误处理

- 周期补记失败：保留已存在数据，提示本次补记失败；下一次启动继续按防重复规则补记。
- 导入失败：不覆盖现有数据库，并给出失败原因。
- 删除账户：首版不允许删除已有流水关联的账户，只能归档。
- 删除投资资产：已有投资流水或市值快照时只允许归档。
- 金额输入：金额必须大于 0，保存前校验。
- 日期输入：不允许周期规则生成早于 `startDate` 或晚于 `endDate` 的流水。

## 测试策略

优先测试 Room 数据层和业务计算逻辑：

- 普通支出正确影响资产账户余额。
- 信用卡消费正确增加信用卡未还负债。
- 信用卡还款不进入消费统计。
- 账户转账不进入收入或消费统计。
- 投资买入减少资产账户余额、增加投资本金，且不进入消费统计。
- 市值快照更新当前市值，并正确计算浮盈浮亏。
- 周期规则能补记到今天。
- 同一 `recurringRuleId + occurrenceDate` 不会重复生成。
- 跳过某一期后不会补记该期。
- 自动补记撤销后能恢复账户和投资资产金额。
- 本月真实消费统计排除投资买入、信用卡还款和账户转账。
- 当前净资产统计包含投资当前市值并扣除信用卡未还负债。
- JSON 导入校验失败时不覆盖现有数据。

UI 测试覆盖关键 Compose 流程：

- 记一笔普通支出。
- 信用卡消费和还款。
- 创建周期账单并触发补记提示。
- 投资买入。
- 更新投资市值。

## 实施顺序建议

1. 创建 Android 原生项目结构。
2. 建立 Room 实体、DAO、数据库和迁移基础。
3. 实现账户、分类和普通流水。
4. 实现统计口径：本月真实消费和当前净资产。
5. 实现信用卡消费和还款。
6. 实现周期规则和启动补记。
7. 实现投资资产、投资买入和市值快照。
8. 实现导出/导入 JSON。
9. 补齐关键业务测试和关键 UI 流程测试。
